# 03 - Project Workflow and Artifacts

> Source: the statement sections "Project workflow" and "Requirements > 2.
> Planning (pipeline)".
> Format reference: folder `docs/phases/phase-02-auth/`.

The project is developed through a **pipeline planning workflow**. Each stage
is a project skill and produces an artifact. You must follow it in order.
**Automatic failure skips the workflow.**

## Pipeline (stage -> skill -> artifact)

| Order | Stage | Skill | Artifact |
|-------|-------|-------|----------|
| 1 | Research options and decide the technical path | `research` | `docs/decisions/technical-decisions-phase-03-videos.md` |
| 2 | Consolidate the phase context | `plan-context` | `docs/phases/phase-03-videos/context.md` |
| 3 | Validate (inconsistencies, missing decisions, gaps) | `plan-validate` | `validation.md` (verdict `clean`/`dirty`) |
| 4 | Resolve pending items and lock libraries | `plan-resolve` | updates decisions/context + `library-refs.md` |
| 5 | Generate the executable plan | `plan-build` | `phase-03-videos.md` |
| 6 | Generate test specs *(optional)* | `plan-test-specs` | test specs |
| 7 | Implement step by step | `implement` | code + `progress.md` |

> The reading sub-agents (`.claude/agents/`) are used internally by the skills
> — you **do not** invoke them directly.

## The validate ⇄ resolve loop

The `validation.md` file points out **missing decisions** and **dependency
gaps**. Iterate `plan-validate ↔ plan-resolve` until `validation.md` closes as
**`clean`**. Only then move to `plan-build`. **Loose plans create loose
implementation.**

> `validation.md` must end with **status `clean`** before implementation. A
> `validation.md` that does not close as `clean` is **automatic failure**.

## The phase folder contract

The phase is a **folder** - `docs/phases/phase-03-videos/` - containing:

```
docs/phases/phase-03-videos/
├── context.md          <- plan-context
├── validation.md       <- plan-validate (status: clean)
├── library-refs.md     <- plan-resolve (new libs fixed via context7)
├── phase-03-videos.md  <- plan-build (the plan)
└── progress.md         <- implement
```

The `library-refs.md` file is **expected in this phase** because it locks new
libraries (storage / queue / FFmpeg).

> **The phase folder format is the contract**; the skill that produces it is an
> implementation detail of the tool. Anything else must produce the **same
> artifacts**, in the same sequence.

## Plan format (`phase-03-videos.md`)

The plan is organized into **Step Implementations** (`SI-03.1`, `SI-03.2`,
etc.), with:

- **Technical Specifications**:
  - **Data Model**
  - **API Contracts**
  - **Authorization Matrix**
  - **Error Catalog**
  - **Events/Messages** <- mandatory in this phase, because of the queue
- **Dependency Map**
- **Deliverables**

The reference plan structure is confirmed in
`docs/phases/phase-02-auth/phase-02-auth.md` (headings: `Objective`,
`Step Implementations` with `SI-02.x`, `Technical Specifications` with `Data
Model` / `API Contracts` / `Authorization Matrix` / `Error Catalog`,
`Dependency Map`, `Deliverables`).

> ⚠️ A plan **without SIs** or **without the Technical Specifications** is
> **automatic failure**.

## Traceability

Every piece of information in the artifacts must be traceable to the plan or
the code. The AI presence must be **observable in the repository**: technical
decisions, planning artifacts, phase plan, and progress, all generated by the
workflow.
